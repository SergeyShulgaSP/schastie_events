- **Решение по дублям:** правило пользователя «одна фамилия = одна сделка». Склейка по номеру договора отключена: номер = последние 4 цифры телефона клиента и совпадает у разных людей (а префикс 2249 есть почти у всех). Строки без фамилии присоединяются по номеру договора, только если он однозначен. Фамилии на «-ич» (Бабич) не путать с отчествами.
- **Решение по суммам:** сумма сделки = «Сумма сделки», если есть, иначе сумма платежей с одного листа (не складывать листы между собой). Суммы «Лист1» (2024) — по словам пользователя, доход по сделке за вычетом расходов (поле `profit`); соседняя колонка ≈ 10% дохода (поле `bonus`) — пользователь не помнит её смысл, решено в расчёты не брать. В выручку не включаются. Номера инвойсов и текст в этих колонках отбрасываются.
- **Находка:** около 40% завершённых сделок из таблицы нет в amoCRM или они закрыты в amoCRM как проигранные.
- **Углублённый анализ, 10 направлений** (по чек-листу, блок «на собранных данных»): скрипт `amo_analytics/deep_analysis.py` → `data/deep.json`; Google Док «Углублённый анализ K-truck: 10 направлений» — https://docs.google.com/document/d/1A3glnH9Da_DaQUjIlXL1_NmcpCIqadAdnBzFJ7ODCVg/edit
- **Решения в анализе:** спам исключён; люди склеены по последним 10 цифрам телефона; сверка с таблицей — по фамилии в названии сделки и в контакте (стало 74/46/14/6 вместо 67/55/14/4); портрет клиента — только по ручным заметкам, расшифровкам и задачам (системные шаблоны дают ложные совпадения: «задачу» ≠ «дача», «понимает окупаемость» — шаблон задачи).
- **Цели на I квартал 2027** — черновик в Google Доке «Цели K-truck на I квартал 2027» (5 целей с ключевыми результатами, план по месяцам, еженедельный отчёт). Выбран I квартал: подготовка в декабре, покупки к сезону идут в январе–марте. Целевые цифры — предложение, ждут согласования (план продаж, бюджет, ответственные).
